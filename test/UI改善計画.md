# UI・操作性 改善計画(2026-10-30 現状調査より)

ファイルを実際に読んで見つかった課題を、効果の大きい順に並べています。Claude Code に「この計画の P1 から順にやって」と渡せます。

## 現状の課題
| # | 課題 | 根拠 |
|---|---|---|
| 1 | ピンチ拡大ができない | viewport に `user-scalable=no, maximum-scale=1`。小さい文字(10〜12px指定あり)を拡大して読めない |
| 2 | PCでもメニューがハンバーガー内に隠れている | `.sidebar` は既定で `display:none`。ページ移動に毎回2タップ必要 |
| 3 | 起動が重い | zukan_beta.json(1.7MB)を `cache:'no-store'` で毎回取得(Tier表は 2026-10-30 に廃止) |
| 4 | CSSが保守不能 | style.css 約185KB・`!important` 約2,200個。直しても別の上書きに負けやすい |
| 5 | アクセシビリティ不足 | ハンバーガー・×ボタンに aria-label が無いものがある。`:focus-visible` が5か所のみ。ダークモード・動きの抑制(prefers-reduced-motion)未対応 |
| 6 | 手動のキャッシュ回避 | index.html の `?v=` を毎回手で書き換え |
| 7 | 計算機の入力欄が多い | 属性・補正・速度・レベルなど9項目以上が縦に並ぶ。詳細モードの切替はあるが、設定の記憶が無い |

## 改善の順序
**P1(すぐ効く・低リスク)** … 2026-10-30 対応済み(`?v=20261030-ui-p1`)
1. viewport から `user-scalable=no` と `maximum-scale=1` を削除
2. JSONの `cache:'no-store'` をやめ、更新確認だけ行う読み込みに
3. PC幅(900px以上)ではサイドバーを常時表示、スマホはハンバーガーのまま。ハンバーガーに aria-label
4. 計算機の「詳細モード」「問題レベル」「自力モード」を localStorage に記憶
5. 数値入力に `inputmode="decimal"`、フォーカス枠(:focus-visible)を全ボタンに

**P2(体験の改善)**
6. 計算結果を画面上部に固定(スマホで入力しながら結果が見える)
7. 図鑑: 画像の `loading="lazy"`、検索のデバウンス、条件を URL に残して共有可能に
8. ピッカー(キャラ選択)を最近使ったキャラ順に
9. ダークモード対応(色は 2026-10-30 に `--ui-*` 変数へ集約を開始)

**P3(基盤整理・Claude Codeで進める)**
10. style.css をページ別(base / calculator / zukan / coop)に分割し、`!important` を段階的に削減(2026-10-30 対応済み: base / calculator / catalog / coop / help の5ファイル、`!important` は1か所のみ)
11. `?v=` の自動付与(簡単なスクリプト)
12. スマホ実機相当のスクリーンショット比較で表示崩れを検出

## 守ること
ダメージ計算の結果・保存データ・idは変えない(CLAUDE.md 参照)。
