# 英語物語ツール UIデザイン方針

対象は、GitHub Pagesで公開している静的サイト(eigomonogatari-tools。ビルドなしの素のHTML/CSS/JS)。ユーザーが2026-11-07に調査と比較を経て決めた方針をまとめている。UIを新しく作る、直す、ページを追加するときは、この方針に従う。

## 最初に守ること(作業ルール)

1. **公開側のファイルを勝手に変更・プッシュしない。** 作業は作業用ブランチか test/ フォルダで行い、公開されているルート直下のファイルへの反映は、ユーザーが見て許可してから行う。
2. リポジトリの `test/CLAUDE.md` を必ず先に読み、その規則に従う。特に次の点。
   - ダメージ計算ロジック(calculator.js / coop.js)、localStorageのキー名・保存形式、要素のid・data-*属性は、頼まれない限り変えない。UI変更で計算結果が変わらないこと。
   - 色・角丸・太さは base.css の `:root` の `--ui-*` 変数を使い、色コードを直接書かない。
   - `!important` は `[hidden]` の1か所だけ。後ろで同じセレクタを定義し直さない。
   - 変更したJS/CSSは index.html の `?v=` を更新する。
   - 図鑑とキャラ選択のUIは常に同時に直す(共通部品)。
   - 画面確認はスマホ幅(375px)とPC幅(1280px)の両方で行い、文字が枠からはみ出さないことを確かめる。
3. 返答とコミットメッセージは日本語。
4. フォントやライブラリなど、外部から新しく読み込むものを足すときは、先にユーザーに確認する。

## 方向性

「ツールとして静かで、きれいで、長く使える」こと。ホームページではなくツールなので、**説明文のヒーロー(「〜を選ぶだけ」のような文)は置かない。** 差は色の派手さではなく、余白、字の細さ、罫線、色を使う場所の少なさでつける。

参考にした調査(17サイト)の傾向: 日本企業は白地、見出しは400〜600の細め〜中くらい、ボタンの角丸は8px前後が最多、大きい英数字は字間を詰める。

### 配色(黒鉛と朱。値は `--ui-*` 変数にまとめる)

| 役割 | 値 |
|---|---|
| 主役(結果の帯、主ボタン、見出し文字) | #24262b |
| 補助の文字(ラベル) | #666b73(白地で5.36:1) |
| 本文の濃い灰色 | #474a51 |
| 罫線 | #e8e8ea |
| 入力欄・背景の面 | #f6f6f7 |
| 選択中の背景 | #efeeee |
| アクセント(朱・文字用) | #b73a17(どの背景でも4.5:1以上) |
| アクセント(朱・文字以外の印や点) | #c8401c |
| 結果の帯の補助文字 | #b0b3b9 / #d6d8db |
| 状態(撃破判定などの点) | #e0b252 |

- 朱は「選択中のメニュー」「変更などのリンク」の2か所だけに使う。広い面には使わない。
- 火=赤、木=緑のような属性の色は、ゲームのデータを示す場所にだけ小さな点で使う(例: 火 #e5603f、木 #3b9a62)。ほかの属性や、既存の攻=赤・守=青の役割色は、既存の変数を壊さず維持する。
- 背景のにじみ(淡いオレンジ〜黄の放射状グラデーション、不透明度約.38)は任意の飾り。置く場合はページ右上の1か所だけにする。
- 文字のコントラスト比は4.5以上を保つ。色を足したら計算して確かめる。

### 文字

- 本文はシステムの日本語フォント(または承認を得て Noto Sans JP)。太さは400〜500。見出しも500まで。700以上は使わない(ロゴなどの小さい箇所を除く)。
- 数字は `font-variant-numeric: tabular-nums`。大きい数字(予想ダメージ)は細めで、字間を少し詰める。
- ラベルは12px、本文は13.5〜14px。英字の大文字ラベル(eyebrow)は使わない。

### レイアウト

- **PC幅(1000px以上): 左メニュー。** 幅約204px、白地、右に細い罫線。ロゴ、6項目(計算機、図鑑、協力ダメージ計算、協力報告書作成、使い方、データ移行)、下にお気に入り。選択中は #efeeee の背景と朱の文字。既存の「文字あり/アイコンだけ」の切り替えは残す。
- **スマホ幅(640px以下): 下タブ。** 画面下に固定し、5項目(計算機、図鑑、協力計算、報告書、その他)。「その他」に使い方とデータ移行をまとめる。上には細いバー(ロゴとお気に入り)だけ置く。iPhoneの下の余白(safe-area)を考慮する。
- ページ上部は、ページ名(20px、太さ500)と右側の操作ボタン(使い方、攻守を入れ替え、詳細モード、全リセット)の1行だけ。
- 計算機: 白いカード(角丸14px、影は薄く長く)の中に、左右に攻撃キャラと攻撃対象。各列の上にキャラ(頭文字の枠か画像、名前、変更リンク)、その下に項目を2列で並べる。下に主役色の帯で予想ダメージを大きく出し、右に撃破判定、与ダメージ割合、残りHP。スマホでは列を縦に積む。
- 他のページ(図鑑、協力ダメージ計算、協力報告書、使い方、データ移行)も、同じ見出し行、同じカード、同じ入力部品でそろえる。

### 部品

- 入力欄: 背景 #f6f6f7、内側に細い罫線、角丸8px、余白は縦7px横11px。
- 2択の選択は切り替えスイッチ(セグメント): 外枠 #f6f6f7、選択中は白い面と薄い影。
- ボタンは2種類だけ。主ボタン=主役色(#24262b)の丸い塗り、補助ボタン=白地に細い枠の丸いボタン。個別に色や枠を足さない。
- 影は、カード1枚に使う薄いものだけ。多用しない。
- 動きは、操作に反応するもの(開閉など)だけ。`prefers-reduced-motion` を尊重する。キーボードのフォーカス枠(:focus-visible)を必ず残す。

## 使わないもの(ユーザーが苦手と言ったもの)

- 黒い背景、黒に黄色などの強い色の組み合わせ、薄暗い画面
- 太い文字、個性の強い飾り文字
- 方眼紙、付箋、手書き風
- 和風(縦書き、明朝、薄灰色の壁紙風)、レトロゲーム風、子供向けの丸いポップな見た目
- 青〜紫のグラデーション、`rounded-2xl` と影の多用、ぼかしガラス、絵文字のアイコン、同じカードを3枚並べる構成

## 作業手順

1. `test/CLAUDE.md` と `base.css` の `:root` を読み、既存の `--ui-*` 変数を確認する。
2. 配色の値を `--ui-*` 変数に反映する(青系の値を、上の配色に置き換える)。
3. メニューをPCの左メニューとスマホの下タブにする(index.html のサイドバーと app.js の toggleMenu / syncMenuToggle を確認してから)。
4. 計算機、図鑑、協力ダメージ計算、協力報告書、使い方、データ移行の順にそろえる。図鑑とキャラ選択は同時に。
5. スマホ幅(375px)とPC幅(1280px)のスクリーンショットで、崩れ、文字のはみ出し、コントラストを確認する。
6. ダメージ計算の結果が変わっていないことを、数値の入力例で確かめる。
7. `?v=` を更新する。ユーザーに見せて許可を得てから、公開側へ反映する。
